# Research and solution alternatives

Research performed on 2026-10-09 using primary documentation, upstream issue history and related repository code.

| Component / source                                                                                                                     | Useful existing capability                                                                                                    | Decision                                                                                                                                                                                                                |
| -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Docker resource constraints](https://docs.docker.com/engine/containers/resource_constraints/)                                         | Memory/CPU flags and daemon-enforced limits; memory-swap is the combined ceiling and matching memory disables additional swap | Reuse existing CLI transport, resolve percentages with daemon `MemTotal/NCPU`; no local RAM/CPU guesses. Validate positive units and range bounds before launch.                                                        |
| [Docker update](https://docs.docker.com/reference/cli/docker/container/update/)                                                        | Updates a container's resource limits                                                                                         | Finish updates before start; pass replacement limits at creation. CPU lifting uses finite base/daemon capacity, respecting the zero-update behavior observed in #189.                                                   |
| [Kernel cgroup v2 interfaces](https://docs.kernel.org/admin-guide/cgroup-v2.html#memory-interface-files)                               | Own-cgroup peak/limit and cumulative events                                                                                   | Sample locally when ID-attributed; otherwise exec through the daemon only in a private namespace. Preserve the last valid sample during outages. Historical events stay observations.                                   |
| [Hive Mind CPU state machine](https://github.com/link-assistant/hive-mind/blob/issue-2801-f9bf1f787e57/src/docker-cpu-penalty.lib.mjs) | Pure hysteresis logic and downstream flag names                                                                               | Use its interface and integration lessons. Implement timestamp-weighted coverage explicitly so irregular sampling cannot fabricate a full busy window.                                                                  |
| [dockerode](https://github.com/apocas/dockerode)                                                                                       | Node Docker Remote API including streams and container update                                                                 | Suitable if replacing CLI transport; unnecessary dependency and transport migration for this change. Existing CLI already respects contexts, remote and DinD configurations.                                            |
| [Bollard](https://github.com/fussybeaver/bollard)                                                                                      | Rust asynchronous Docker API, Unix sockets, Windows named pipes and optional HTTPS                                            | Same alternative for Rust. Keep existing synchronous command-runner injection and transport for behavioral parity.                                                                                                      |
| [proper-lockfile](https://github.com/moxystudio/node-proper-lockfile)                                                                  | Atomic mkdir, mtime heartbeat, retry and compromised-lock handling                                                            | Helpful design reference. Adding only the JS library would leave Rust using an incompatible lock protocol. Preserve cross-language JSON lock ownership with atomic populated-file publication and malformed-lock grace. |
| [fs2 FileExt](https://docs.rs/fs2/latest/fs2/trait.FileExt.html)                                                                       | Advisory flock/Windows LockFile                                                                                               | Good native-lock alternative, but requires an equivalent JS native protocol and migration for shared stores. A small common file format avoids that migration.                                                          |
| [Docker live restore](https://docs.docker.com/engine/daemon/live-restore/)                                                             | Keeps supported Linux containers running through daemon unavailability                                                        | Document as an operator workaround for #194. It does not repair stale OOM attribution or store persistence, and has configuration/upgrade limits.                                                                       |
| [Moby #43564](https://github.com/moby/moby/issues/43564)                                                                               | Existing report of OOMKilled after a child OOM                                                                                | Treat the flag as an observation; report the downstream interpretation fix instead of filing a duplicate flag-semantics bug.                                                                                            |

Randomizing launch/recovery limits spreads cap thresholds; it does not reserve RAM or guarantee that several tasks fit together. Snapshot serialization/disk preflight is a downstream storage-policy solution, while durable prelaunch records and atomic writes directly fix start-command's tracking bug.

[Moby's container update validation](https://github.com/moby/moby/blob/v28.5.0/container/container_unix.go) rejects changing an existing CPU period/quota to NanoCPUs, or the reverse. Penalty transitions and in-place overrides preserve the inspected representation; finite quota restoration also respects the original lower base.

The chosen plan reuses existing HostConfig translation, attempt markers, detached watcher, runtime arguments and kill-delay machinery. Every policy module has matching JavaScript/Rust implementations and regression files #189–194. Attached diagnostics and disabled-tracking monitors use the same policies; JS stacked Docker launches carry raw specifications until the Docker level resolves them.
