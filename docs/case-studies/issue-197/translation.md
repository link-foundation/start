# Executable generation and exact remaining blockers

The pinned translator at `eb0574d5528babd3b4aadece81590d8e2230b99b` translates the typed arithmetic policy in `scripts/parity-threshold.mjs` into executable Rust. Both native tests execute the generated policy against `parity/fixtures/contracts.json`; the count diagnostic imports the same JavaScript policy. `generate-rust.mjs --check` calls upstream `selfTranslate` again, rejects carried/unsupported items and compares the full output. A stale hash or a checked-in comment is not accepted as generation.

The published npm package was `0.46.0` during investigation and lacks the current `selfTranslate` API. The GitHub main source has newer self-translation, so setup fetches the immutable upstream commit and installs its locked production dependencies. This avoids accidentally substituting an obsolete npm API or a moving branch. The snapshot of upstream translation contracts, package, source and open issues is in `data/`.

## Manual inventory and limits

Every non-generated file under `rust/src` is listed in `parity/features.json` with its feature, reason and upstream blockers. `translationBlockers` anchors each applicable construct to an actual JavaScript source file and line. The inventory checker fails if any new source or manual Rust file is omitted. Generated files are identified separately in `parity/translation.json`.

The existing native Rust port remains substantial. The supported arithmetic policy is a small real generated unit; it does **not** prove that the process/isolation/store adapters can be generated today. Removing the native port would remove working public features. The issue's documented-blocker alternative is therefore used for those modules, with shared behavioral contracts and narrow manual changes. Future generation should replace one supported feature at a time, compile its native output, run shared fixtures, then remove the corresponding manual inventory entry. Merely wrapping all unsupported source in comments would hide missing behavior.

Meta-language's [translation rules](https://github.com/link-foundation/meta-language/blob/eb0574d5528babd3b4aadece81590d8e2230b99b/docs/translation-rules.md) and [four-language contracts](https://github.com/link-foundation/meta-language/blob/eb0574d5528babd3b4aadece81590d8e2230b99b/docs/four-language-contracts.md) provide the upstream semantic contract. The exact saved snapshots in `data/` are the evidence used for this implementation.
