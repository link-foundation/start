### Checked and left as is

- The rust.yml check jobs use `cancel-in-progress: false` on purpose. This is tested by `read_only_checks_protect_main_and_the_gated_rust_stage`.
- Gating Rust behind the JS stage is the project's JavaScript-first design.
- The warnings in `analysis/ci-warnings-scan.txt` are expected test output, CodeQL's schema dump, or already fixed (`cargo publish --token`).
- Crates.io publishing already treats "already uploaded/exists" as success, and `cargo publish` waits for the index itself.

## Online references

- GitHub: events triggered by `GITHUB_TOKEN` do not create workflow runs
  (https://docs.github.com/en/actions/security-for-github-actions/security-guides/automatic-token-authentication).
  peter-evans/create-pull-request documents the same in its
  ["Triggering further workflow runs"](https://github.com/peter-evans/create-pull-request/blob/main/docs/concepts-guidelines.md#triggering-further-workflow-runs) section.
- GitHub: pass untrusted values through an intermediate environment variable
  (https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions).
- ESLint `--max-warnings` (https://eslint.org/docs/latest/use/command-line-interface).
- lychee caching needs the `.lycheecache` file persisted between runs
  (https://lychee.cli.rs/recipes/caching/, https://github.com/lycheeverse/lychee-action).
- macOS `path_helper(8)`: run from `/etc/profile`, it builds `PATH` from `/etc/paths` and `/etc/paths.d`.
